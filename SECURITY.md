# Безопасность

## Поддерживаемая версия

Репозиторий является демонстрационным прототипом. Исправления безопасности вносятся только в основную ветку.

## Как сообщить об уязвимости

Не публикуйте сведения об уязвимости и доказательство эксплуатации в открытом обсуждении. Используйте закрытое сообщение владельцу репозитория через GitHub. Укажите затронутый компонент, условия воспроизведения, возможное влияние и безопасный способ проверки.

Не прикладывайте настоящие токены, пароли, персональные данные или снимки рабочих баз.

## Эксплуатационные ограничения

- Проект не готов к размещению в открытой сети: пользовательская аутентификация ещё не реализована.
- Административное API должно оставаться выключенным, если для него не настроен отдельный длинный токен.
- Разрешённые списки HTTP- и JDBC-узлов по умолчанию должны оставаться пустыми.
- Секреты хранятся только в локальном `infra/.env` или во внешнем хранилище секретов.
- Значения, которые когда-либо находились в истории Git, следует считать раскрытыми и заменить перед использованием.
