# Orchestra

Orchestra — прототип платформы для проектирования и выполнения интеграционных сценариев по BPMN- и PlantUML-процессам. Система хранит процессы, спецификации, сценарии и наборы данных, ставит запуски в RabbitMQ и выполняет шаги HTTP, PostgreSQL и Kafka отдельным исполнителем. Сервис на Spring AI и Ollama помогает формировать сценарии и тестовые данные.

## Состав проекта

- `services/orchestra-domain` — предметные сущности, репозитории и общие контракты;
- `services/orchestra-api` — HTTP API, планирование запусков, импорт и работа с данными;
- `services/orchestra-executor` — получение заданий из RabbitMQ и выполнение протокольных шагов;
- `services/ai-service` — локальная генерация через Ollama и pgvector;
- `apps/orchestra-web` — интерфейс React, TypeScript и Vite;
- `infra` — локальное окружение Docker Compose;
- `docs` — архитектурные материалы, технический аудит и подготовка к собеседованию.

## Важная граница безопасности

Текущая общедоступная версия предназначена только для локального однопользовательского показа:

- внешняя аутентификация пользователей ещё не реализована;
- организация задаётся серверной переменной `ORCHESTRA_TENANT_ID` и не принимается из заголовков клиента;
- административное API по умолчанию выключено;
- внешние HTTP- и JDBC-адреса запрещены, пока оператор явно не добавит узлы в разрешённые списки;
- изменения данных через JDBC-исполнитель по умолчанию запрещены;
- служебные порты привязаны к `127.0.0.1`, а сервис моделей в основном окружении доступен только внутри сети контейнеров.

Не размещайте это окружение в интернете без полноценной аутентификации, разграничения прав, сетевой изоляции и управления секретами.

## Требования

- Docker с Docker Compose;
- для запуска без контейнеров: JDK 21, Maven 3.9, Node.js 22 и npm;
- локальный Ollama требуется только для функций генерации.

## Локальный запуск

1. Создайте локальный файл настроек:

```bash
cp infra/.env.example infra/.env
```

2. Заполните пустые значения длинными случайными строками. Не используйте примеры как рабочие секреты и не добавляйте `infra/.env` в Git.

3. При необходимости задайте разрешённые узлы:

- `ORCHESTRA_HTTP_ALLOWED_HOSTS` — точные имена узлов для HTTP-шагов;
- `ORCHESTRA_HTTP_ALLOW_PRIVATE_NETWORKS` — разрешение частных адресов, по умолчанию `false`;
- `ORCHESTRA_DB_ALLOWED_HOSTS` — узлы PostgreSQL для шагов исполнителя;
- `ORCHESTRA_RESOLVER_DB_ALLOWED_HOSTS` — узлы PostgreSQL для разрешения наборов данных;
- `ORCHESTRA_DB_ALLOW_MUTATIONS` — изменение данных, по умолчанию `false`.

4. Запустите окружение:

```bash
cd infra
docker compose up --build
```

Интерфейс будет доступен на `http://127.0.0.1:3000`, API — на `http://127.0.0.1:8085`.

## Проверки

Серверные модули:

```bash
cd services
mvn -B verify
```

Веб-интерфейс:

```bash
cd apps/orchestra-web
npm ci
npm run lint
npm test
npm run build
```

Конфигурация контейнеров:

```bash
cd infra
docker compose config --quiet
```

Эти же проверки выполняются в GitHub Actions для каждого запроса на слияние.
